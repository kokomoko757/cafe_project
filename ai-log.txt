DATE: November 8, 2026
TOPIC: Endterm Rubric Audit, Plain JS vs jQuery Strict Separation & Unit Test Suite

1. AUDIT FINDINGS AGAINST 100-POINT RUBRIC
--------------------------------------------------------------------------------
During the final verification pass against `requirements.txt`, an architectural
rubric risk was detected:
- The rubric strictly penalizes having only jQuery on the live site ("A project
  with only plain JS or only jQuery loses the points for the missing half.
  Keep the two apart: a feature is either plain JavaScript or jQuery, never both,
  and keep them in separate files").
- In an earlier iteration, all interactive features had been ported to jQuery,
  leaving Vanilla JS solely in `old-js-version.js` (unlinked from live HTML).
- To guarantee full score for Weeks 6–8 (20 pts Plain JS + 14 pts Events/Delegation
  + 16 pts Validation), Table Booking (`booking.html`, `details.html`, `js/booking.js`)
  was refactored into 100% native Vanilla JavaScript with zero jQuery calls.
- Online Order (`order.html`), Menu (`menu.html`), Reviews (`reviews.html`),
  Locations (`location.html`), and Franchise (`partner.html`) remain 100% jQuery 3.7.1.
