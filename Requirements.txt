Step 0. This is a continuation — and the last assignment
We keep working on the same project. You do not start a new project and you do not create a new repository — it is the same team, the same organization, the same theme and the same pages you have been building since Assignment 1, and now you add jQuery to them. This is the final assignment before the project defense, so whatever you leave broken here stays in the project you defend. The freeze from the midterm still holds: you do not write new HTML elements by hand and you do not write new CSS rules by hand — new elements are created in code, and appearance is changed by switching classes you already wrote. You may still add an id or a class to an existing element when your code needs a hook.
Connecting jQuery
Link jQuery from a CDN in every page that uses it, and link your own script after it — your code cannot call a library that has not loaded yet. Put your code inside $(document).ready(), or its short form $(function () { ... }), and write in a comment which version of jQuery you are using and why that line is needed. Keep your JavaScript in separate .js files — no code written inside the HTML, and no onclick attributes in the markup.
Rewrite what you already wrote
Take three features you wrote in plain JavaScript in the previous weeks — for example the form validation, the show-and-hide of a block, and the list you build in code — and rewrite them with jQuery. Keep the old plain-JavaScript version of those three in a separate file named old-js-version.js, which is not linked to any page, so both versions can be compared side by side. Above each rewritten feature write a comment of one or two lines: which jQuery methods replaced which plain-JavaScript lines, and whether the result is actually shorter and clearer. If it is not, say so — that is a real answer and it scores full marks.
Selectors, traversal and chaining
Across the project use a selector by id, by class, by element and by attribute, and at least one filter such as :first, :last, :checked or :not(). Use traversal where it genuinely helps instead of adding more ids: .find(), .closest(), .parent(), .siblings() and .each() — for instance, from a clicked button reaching the card it belongs to. Use $(this) inside at least two handlers. Write at least two chains of three or more methods, and add a comment on one of them explaining what each link in the chain does.
Changing the page
Use .text(), .html(), .val(), .attr() and .prop() in places where each is the right choice, and be ready to explain the difference between .text() and .html(), and between .attr() and .prop() on a checkbox. Change appearance only with .addClass(), .removeClass(), .toggleClass() and .hasClass() on classes that already exist in your stylesheet. Build at least one list or set of cards from an array in your code with .append() or .appendTo(), so the markup for those items exists nowhere in your HTML file.
Events and delegation
Attach every handler with .on(). Use at least three different event types — for example click, submit, input, change, mouseenter or keyup. At least one handler must be delegated: bound to a parent that already exists and reacting to elements created later, written as $("#list").on("click", ".item", handler). Then explain in a comment why binding it directly to .item would not work for the items your own code creates. Use event.preventDefault() where it belongs and say in a comment what would happen without it.
Effects
Use at least three effects with a real purpose — .fadeIn(), .fadeOut(), .fadeToggle(), .slideUp(), .slideDown(), .slideToggle() or .animate() — on things such as an FAQ answer, a confirmation message or a filter panel. Pass a duration to at least one of them, and use a callback that runs after the effect finishes at least once. Decoration for its own sake does not count: an effect must belong to something the visitor actually does.
Form validation with jQuery
Rebuild the validation of your main form in jQuery. On submit, prevent the default, check every field, and for each invalid field add an error class and show a message next to that field, not one message for the whole form. Trim the values before checking them, check the format of the e-mail and the phone, and clear the error as soon as the visitor fixes the field. Show the success message only when every check passes, and reset the form afterwards. Keep the browser attributes such as required in place as the first line of defence, and say in a comment why a check in the browser never replaces a check on the server.
Forbidden
No downloaded jQuery plugins, no sliders or galleries taken ready-made, no templates. No new hand-written HTML elements and no new hand-written CSS rules — the freeze still applies. Do not mix approaches inside one feature: if a block is handled with jQuery, it is not also handled with document.getElementById. Inline event attributes such as onclick in the HTML cost 5 points each.
Submission
The same repository: your jQuery file or files, old-js-version.js for comparison, an updated AI log and README. There is no written report and nothing to record — everything is shown live at the defense. Everyone commits from their own account, at least four commits across three different days, six if you work alone. The browser console must show no errors on any page.
Defense
You open the site in front of me and show the features working — the delegated handler, the effects and the validation. Then I will point at a line of your jQuery and ask what it does and what the plain-JavaScript equivalent would be, ask why a delegated handler catches elements that did not exist yet, ask the difference between .text() and .html(), and give you small live tasks — change an effect, add a field to the validation, make a chain do one more thing, or make a button build one more item in the list. I may also give you a small practical task on any topic from the whole course, plus a few oral questions from the lectures. You may look at the official documentation and w3schools.com during the defense, but not ask another person or an AI. Work that is submitted but not defended is not evaluated, even if it was uploaded before the deadline.
Grading (100 points)
Rewriting the three plain-JavaScript features, with the comparison comments 18 · selectors, traversal and chaining 15 · changing the page, including the list built from an array 15 · events and delegation 20 · effects 10 · form validation in jQuery 17 · console without errors and commit history 5. Penalties: 10 for a downloaded plugin or ready-made component, 10 for new hand-written HTML or CSS, 5 per inline onclick attribute, 5 per console error, 5 for mixing jQuery and plain JavaScript inside one feature.
